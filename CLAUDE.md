# wilds-of-osse-homebrew

Homebrew content for the Wilds of Ossë D&D 5e campaign, packaged for 5e.tools, plus the game master screen pages in `screen/`. Players load the combined file by its raw link.

Change model: Direct. Commit to main.

## Commands
- Build: `python3 tools/build.py` (merges `src/` into `wilds-of-osse.json`)
- Check before every commit: `python3 tools/check_secrets.py && python3 tools/build.py && python3 -c "import json; d=json.load(open('wilds-of-osse.json')); assert d['_meta']['sources']; print(len(d.get('monster', [])), 'creatures')"`
- The pre-commit hook in `.githooks/` runs the secret check on staged files. On a new clone, turn it on with `git config core.hooksPath .githooks`. GitHub push protection and the `check-secrets` workflow back it up.

## Where things live
- `src/`: the content, one file per group, and `_meta.json` (source block, version, timestamps). Edit these.
- `wilds-of-osse.json`: the combined file players load. Generated; never edit it by hand.
- `tools/build.py`: the merge script.
- `index.html`: the table hub (site home page). Player links and codes first, then game master links behind a passcode. Its link lists are at the top of its script; keep them current.
- `screen/`: game master screen pages. One page per session, `screen/sNN.html`, with an iPad layout (`#ipad`) and a tall 1080p layout (`#tall`).
- `relay/gus/`: the AWS relay behind `screen/gus.html` (Gus's memory archive). `deploy.sh` deploys it; keys live in the macOS Keychain.
- `.claude/skills/session-screen/`: how to build and publish a session screen. Follow it for every new one.
- `chronicle/`: the players' chronicle page. `chronicle.json` is generated by `tools/chronicle.py export` from the Ossë vault's `Chronicle/` folder; never edit it by hand.
- `.claude/skills/chronicle/`: how to add a session to the chronicle. Follow it after every session.
- `tools/osse/`: the Ossë vault's tools. `osse.py` answers questions compactly, `build.py` rebuilds and checks the vault, `graph.py` walks it, `vocab.py` maps every type and link to a standard term.
- `docs/osse/`: the vault's rules (README first). Examples are made up.
- `.claude/skills/post-session/`: the post-session sync. Follow it after every session.
- `.claude/skills/gus-document/`: how to write a new Gus document and file it, sealed, in Gus's archive. Follow it for every new one.
- `.github/workflows/build-homebrew.yml`: rebuilds and commits the combined file when `src/` changes.

## Conventions
- Follow the 5e.tools homebrew schema. Keep each creature in the file for its group.
- After the Action rebuilds the combined file it commits to main, so pull before the next change.

## The Ossë vault
The campaign's truth lives in the Ossë Obsidian vault in iCloud, outside this repo. All vault work runs from here.
- Start any campaign question with `python3 tools/osse/osse.py brief`, then `card NAME` or `find TEXT`. Open notes only to edit them.
- After any vault change, `python3 tools/osse/build.py` and fix every problem it prints.
- `vault/` holds a DM page for every vault note, rebuilt by `build.py`. It is a DM screen: link it only from the hub's game master section.
- `codex/` is the players' version: only notes the table has met, only lines stamped with a played session. It is a player screen; it never links to `vault/`.
- `vault/paths.html` (Paths ahead, from `tools/osse/paths.py`): Tom's planning board, one per character, with a tab per session and a tray of unplaced plans. He drags, links, adds, edits and deletes cards, and adds or deletes sessions; a scene shows on the board of every player character present, and everything has one copy; its Session plan adds scenes and players and puts a session's scenes in running order; a decision's options are the links out of it; it saves to the Gus relay (`paths.json`). `tools/osse/paths_sync.py` reads it and drafts onto it (`board`, `draft`, `undraft`). DM screen only.
- `.claude/skills/paths/`: draft Tom's brain dumps and clean-ups onto the boards, and bring the boards into the vault. Follow it when he asks for either.
- `vault/status.json` (also rebuilt by `build.py`) drives the hub's launchboard: the next session, its screen, and the checklist's automatic ticks.
- The two boundaries (player screens vs DM screens, real-world secrets vs game secrets) are in `docs/osse/README.md`.

## Hard rules
- Never rename or move `wilds-of-osse.json`, and never rename the repository or the `main` branch: players' saved raw link depends on all three.
- This repository is public. No real-world secrets or personal details (keys, tokens, passwords, signed URLs, codes, emails, addresses): `python3 tools/check_secrets.py` must pass before every commit. Game content, including game secrets, is fine.
- Player screens show only what has come out in play. Unrevealed game secrets, prep and plans stay on DM screens.
